3x-ui can drive a Telegram bot for monitoring, alerts, backups, and remote
management. Admins get full control; regular users (linked by Telegram ID) can
check their own usage and links.

<Callout type="info">
  Looking for news and community support? Join the official Telegram channel
  [@XrayUI](https://t.me/XrayUI). That's separate from the bot below, which you
  run yourself to manage your own panel.
</Callout>

## Set it up

<Steps>

<Step>
### Create a bot

Message [@BotFather](https://t.me/BotFather), send `/newbot`, and copy the **bot
token**.
</Step>

<Step>
### Find your Telegram ID

Get your numeric Telegram user ID (the bot's own `/id` command reports it once
connected). This is your **admin** ID.
</Step>

<Step>
### Configure the panel

In Panel Settings, enable the Telegram bot and set the **token** and **admin chat
ID(s)** (comma-separated). Save, then message your bot.
</Step>

</Steps>

## Commands

Everyone's command menu holds the account commands; each admin's own chat gets
the admin set. Everything is also reachable by buttons, and the account and admin
menus are in Chinese.

| Command          | Who    | Action                                                                 |
| ---------------- | ------ | ---------------------------------------------------------------------- |
| `/start`         | anyone | The admin menu for an admin, the account menu for a linked user, how to link for anyone else; `/start <code>` links the account the activation code names |
| `/report`        | user   | Usage: remaining traffic, today's use, next reset, expiry, IPs online  |
| `/ips`           | user   | The IPs online now, relays never among them, and running bans with the time left |
| `/daily`         | user   | Daily report settings; also `/daily on`, `/daily off`, `/daily 21:30` (Beijing time) |
| `/bind <code>`   | anyone | Link with an activation code; sending the bare code works too          |
| `/help`          | anyone | How the bot works                                                      |
| `/users`         | admin  | Every user, ten a page, with status, IP slots and expiry               |
| `/user <name>`   | admin  | Find users by part of the name; a single hit opens its card            |

`/status`, `/id`, `/usage <arg>`, `/inbound <remark>` and `/restart` work as
before.

### Linking an account

A user is a Telegram account linked to a client. In the user page,
**我的激活码** → **一键绑定 Telegram** opens the bot with the account's
activation code, and pressing Start links it; sending the code to the bot works
too, in any case and with or without dashes. One code links one account to one
Telegram account, and each Telegram account gets five tries an hour. The link is
written into every inbound the client is on, so saving an inbound never drops it.

### The account menu

A linked user's `/start` shows their status, remaining traffic as a bar, the
expiry with the days left, the IPs online and any running ban or strikes, with
buttons for the usage details, the devices online, the daily report, the ban
history (**封禁记录**, the last 90 days with when and why) and help, which also
lists the usage rules. A button replaces the
message it is on; one under a notification opens a new message instead, so the
report or alert stays.

### The admin menu

The admin's `/start` counts users online, users due for renewal, expired,
used-up and disabled users, running IP bans and nodes online. **用户列表** and
**需要续期** (due within a week, lapsed within a month, or nine tenths through
the quota) lead to a user's card: plan, usage, expiry, the IPs online and bans.
From the card an admin can:

- **续期** — add 7 days, or 1, 3 or 6 months or 1 year by the calendar, clearing
  the usage unless unticked, the same renewal as on the users page. A month ends
  on the same date of the next month (UTC+8), on its last day when that month is
  shorter, and a user on the 31st comes back to it. A plan sold by terms offers
  only its months. The confirmation shows the expiry before and after, and
  pressing it twice renews once.
- **清零流量** — reset the usage on every server; a user the quota cut off comes back.
- **停用 / 启用** — on every inbound the user is on.
- **解封 IP** — lift an IP-limit ban.
- **解除封禁** — end an abuse ban; ending a lock also clears the strikes.
- **清除违规** — clear the strikes; the history keeps the bans, marked.
- **封禁记录** — the user's bans of the last 90 days.

**更多工具** opens the original admin buttons: server usage, the sorted traffic
report, backups, ban logs, inbounds, online clients, the add-client wizard,
broadcast and the rest.

## Reports & alerts

- **Periodic report** — on the `tgRunTime` schedule (default `@daily`), the bot
  sends admins server usage (host, versions, uptime, load, memory, online
  clients, traffic), a list of exhausted/expiring clients, and — if
  `tgBotBackup` is on — a database + Xray config backup. Clients linked by
  Telegram ID get their own expiry/quota warnings.
- **Account notices** — once a minute the bot checks each linked user and, at
  their daily time (default 20:00 Beijing time), sends the daily usage report if
  it is on and a renewal reminder 7, 3 and 1 days before expiry. When the IP
  limit bans one of a user's IPs, the user and the admins are told; the admins'
  message has a button that lifts the ban. Admins also get a reminder 7, 3 and 1
  days before a server's expiry in the probe.
- **Abuse notices** — when [abuse prevention](/docs/operations/security#abuse-prevention)
  bans or locks an account, the user and the admins are told why, with the strike
  number and the time left; the admins' message has buttons that lift the ban and
  open the user. A rule set to warn tells the user at most once an hour. Hits
  that only record reach the admins at once for scans and attacks, at most once
  an hour per user and rule, and otherwise in a digest at 09:00 Beijing time. A
  network that signs up many accounts is reported with the accounts.
- **Event alerts** — selected by `tgEnabledEvents` (default `login.attempt,cpu.high`):

  | Event           | When                                                    |
  | --------------- | ------------------------------------------------------- |
  | `login.attempt` | A panel login succeeds or fails (with IP and username)  |
  | `cpu.high`      | CPU exceeds `tgCpu` percent (default 80)                |
  | `memory.high`   | Memory exceeds `tgMemory` percent (default 80)          |
  | `xray.crash`    | Xray-core crashes                                       |
  | `outbound.down` / `outbound.up` | An outbound goes down / recovers        |
  | `node.down` / `node.up`         | A node goes offline / comes back        |

The warning lead times come from `expireDiff` (days before expiry) and
`trafficDiff` (GB of quota remaining); both default to `0` (off).

## Settings

| Setting        | Default                    | Meaning                                        |
| -------------- | -------------------------- | ---------------------------------------------- |
| `tgBotEnable`  | `false`                    | Master on/off.                                 |
| `tgBotToken`   | _(secret)_                 | Bot API token.                                 |
| `tgBotChatId`  | _(none)_                   | Comma-separated **admin** Telegram IDs.        |
| `tgBotProxy`   | _(none)_                   | `socks5://`, `http://`, or `https://` proxy.   |
| `tgBotAPIServer` | _(default)_              | Custom Telegram Bot API server.                |
| `tgRunTime`    | `@daily`                   | Report schedule (cron / `@daily` / `@every …`).|
| `tgBotBackup`  | `false`                    | Attach a DB backup to the periodic report.     |
| `tgCpu` / `tgMemory` | `80` / `80`          | CPU / memory alert thresholds (percent).       |
| `tgLang`       | `en-US`                    | Language of the original admin tools; the account and admin menus are Chinese. |
| `tgEnabledEvents` | `login.attempt,cpu.high`| Which events to deliver.                       |

<Callout type="warn">
  The bot token controls your bot — keep it secret and only add **trusted** admin
  chat IDs. Login alerts never include passwords.
</Callout>

<Callout type="info">
  Email (SMTP) notifications mirror the same events (`smtpEnabledEvents`) if you'd
  rather receive alerts by email — configure SMTP in Panel Settings.
</Callout>
