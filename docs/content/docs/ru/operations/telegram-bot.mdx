3x-ui умеет управлять Telegram-ботом для мониторинга, оповещений, резервного
копирования и удалённого управления. Администраторы получают полный контроль;
обычные пользователи (привязанные по Telegram ID) могут проверять собственный
расход трафика и ссылки.

<Callout type="info">
  Ищете новости и поддержку сообщества? Присоединяйтесь к официальному
  Telegram-каналу [@XrayUI](https://t.me/XrayUI). Это отдельный канал, не
  связанный с описанным ниже ботом, которого вы запускаете самостоятельно для
  управления собственной панелью.
</Callout>

## Настройка

<Steps>

<Step>
### Создайте бота

Напишите [@BotFather](https://t.me/BotFather), отправьте `/newbot` и скопируйте
**токен бота**.
</Step>

<Step>
### Узнайте свой Telegram ID

Получите свой числовой идентификатор пользователя Telegram (после подключения
бот сообщит его по собственной команде `/id`). Это ваш **админский** ID.
</Step>

<Step>
### Настройте панель

В настройках панели включите Telegram-бота и задайте **токен** и **админские
chat ID** (через запятую). Сохраните, затем напишите своему боту.
</Step>

</Steps>

## Команды

В меню команд у всех — команды аккаунта; в личном чате каждого администратора —
команды администратора. Всё доступно и кнопками; меню аккаунта и администратора
на китайском языке.

| Команда          | Кто            | Действие                                                     |
| ---------------- | -------------- | ------------------------------------------------------------ |
| `/start`         | любой          | Меню администратора для администратора, меню аккаунта для привязанного пользователя, инструкция по привязке для остальных; `/start <код>` привязывает аккаунт, который называет код активации |
| `/report`        | пользователь   | Расход: остаток трафика, расход за сегодня, следующее обнуление, срок, IP онлайн |
| `/ips`           | пользователь   | IP, которые сейчас онлайн (ретрансляторов среди них никогда нет), и действующие блокировки с оставшимся временем |
| `/daily`         | пользователь   | Настройки ежедневного отчёта; также `/daily on`, `/daily off`, `/daily 21:30` (пекинское время) |
| `/bind <код>`    | любой          | Привязать по коду активации; можно просто отправить код       |
| `/help`          | любой          | Как пользоваться ботом                                       |
| `/users`         | администратор  | Все пользователи, по десять на странице, со статусом, слотами IP и сроком |
| `/user <имя>`    | администратор  | Поиск пользователей по части имени; единственный результат сразу открывает карточку |

`/status`, `/id`, `/usage <arg>`, `/inbound <remark>` и `/restart` работают как
раньше.

### Привязка аккаунта

Пользователь — это аккаунт Telegram, привязанный к клиенту. На странице
пользователя **我的激活码** → **一键绑定 Telegram** открывает бота с кодом
активации аккаунта, и нажатие «Старт» привязывает его; можно и отправить код
боту, в любом регистре, с дефисами или без. Один код привязывает один аккаунт к
одному аккаунту Telegram, у каждого аккаунта Telegram пять попыток в час.
Привязка записывается во все inbound клиента, поэтому сохранение inbound её не
сбрасывает.

### Меню аккаунта

`/start` привязанного пользователя показывает статус, остаток трафика полосой,
срок с числом оставшихся дней, IP онлайн и действующий бан или нарушения, с
кнопками подробного расхода, устройств онлайн, ежедневного отчёта, истории банов
(**封禁记录**: последние 90 дней, когда и почему) и справки, где также перечислены
правила использования. Кнопка заменяет сообщение, под
которым находится; кнопка под уведомлением открывает новое сообщение, и отчёт
или предупреждение остаются.

### Меню администратора

`/start` администратора показывает пользователей онлайн, требующих продления,
истёкших, исчерпавших трафик и отключённых, действующие блокировки IP и узлы
онлайн. **用户列表** и **需要续期** (срок в течение недели, истёк в течение
месяца или израсходовано девять десятых квоты) ведут к карточке пользователя:
план, расход, срок, IP онлайн и блокировки. В карточке администратор может:

- **续期** — добавить 7 дней или 1, 3, 6 месяцев либо 1 год по календарю, по
  умолчанию с обнулением расхода, как продление на странице пользователей. Месяц
  заканчивается тем же числом следующего месяца (UTC+8), а в более коротком
  месяце — его последним днём; пользователь с 31-м числом к нему возвращается.
  План, продаваемый по срокам, предлагает только свои месяцы. Подтверждение
  показывает срок до и после, а двойное нажатие продлевает один раз.
- **清零流量** — обнулить расход на всех серверах; пользователь, отключённый по
  квоте, возвращается.
- **停用 / 启用** — во всех inbound пользователя.
- **解封 IP** — снять блокировку лимита IP.
- **解除封禁** — снять бан за злоупотребление; снятие блокировки аккаунта также
  обнуляет нарушения.
- **清除违规** — обнулить нарушения; история сохраняет баны с пометкой.
- **封禁记录** — баны пользователя за последние 90 дней.

**更多工具** открывает прежние кнопки администратора: расход сервера,
отсортированный отчёт по трафику, резервные копии, журналы блокировок, inbound,
клиентов онлайн, мастер добавления клиента, рассылку и остальное.

## Отчёты и оповещения

- **Периодический отчёт** — по расписанию `tgRunTime` (по умолчанию `@daily`) бот
  отправляет администраторам сведения об использовании сервера (хост, версии,
  время работы, нагрузка, память, онлайн-клиенты, трафик), список
  исчерпанных/истекающих клиентов и — если включён `tgBotBackup` — резервную
  копию базы данных и конфигурации Xray. Клиенты, привязанные по Telegram ID,
  получают собственные предупреждения об истечении срока/исчерпании квоты.
- **Уведомления аккаунтов** — раз в минуту бот проверяет привязанных
  пользователей и в их время отчёта (по умолчанию 20:00 по Пекину) отправляет
  ежедневный отчёт, если он включён, и напоминание о продлении за 7, 3 и 1 день
  до срока. Когда лимит IP блокирует IP пользователя, об этом узнают пользователь
  и администраторы; в сообщении администраторам есть кнопка снятия блокировки.
  Администраторы также получают напоминание за 7, 3 и 1 день до срока сервера в
  пробе.
- **Уведомления о злоупотреблениях** — когда [защита от злоупотреблений](/docs/operations/security)
  банит или блокирует аккаунт, пользователь и администраторы узнают причину,
  номер нарушения и оставшееся время; в сообщении администраторам есть кнопки
  снятия бана и открытия пользователя. Правило с предупреждением сообщает
  пользователю не чаще раза в час. Срабатывания, которые только записываются,
  приходят администраторам сразу для сканирования и атак (не чаще раза в час на
  пользователя и правило), а остальные — в сводке в 09:00 по пекинскому времени.
  О сети, зарегистрировавшей много аккаунтов, сообщается вместе со списком аккаунтов.
- **Оповещения о событиях** — выбираются параметром `tgEnabledEvents` (по умолчанию `login.attempt,cpu.high`):

  | Событие         | Когда                                                   |
  | --------------- | ------------------------------------------------------- |
  | `login.attempt` | Вход в панель удался или не удался (с IP и именем пользователя) |
  | `cpu.high`      | Загрузка CPU превышает `tgCpu` процентов (по умолчанию 80) |
  | `memory.high`   | Использование памяти превышает `tgMemory` процентов (по умолчанию 80) |
  | `xray.crash`    | Аварийное завершение Xray-core                          |
  | `outbound.down` / `outbound.up` | Исходящее подключение упало / восстановилось |
  | `node.down` / `node.up`         | Узел ушёл в офлайн / вернулся в строй    |

Время предупреждения определяется параметрами `expireDiff` (дней до истечения
срока) и `trafficDiff` (ГБ оставшейся квоты); оба по умолчанию равны `0`
(отключено).

## Параметры

| Параметр       | По умолчанию               | Значение                                       |
| -------------- | -------------------------- | ---------------------------------------------- |
| `tgBotEnable`  | `false`                    | Главный переключатель вкл./выкл.               |
| `tgBotToken`   | _(секрет)_                 | Токен Bot API.                                 |
| `tgBotChatId`  | _(нет)_                    | **Админские** Telegram ID через запятую.       |
| `tgBotProxy`   | _(нет)_                    | Прокси `socks5://`, `http://` или `https://`.  |
| `tgBotAPIServer` | _(по умолчанию)_         | Пользовательский сервер Telegram Bot API.      |
| `tgRunTime`    | `@daily`                   | Расписание отчётов (cron / `@daily` / `@every …`).|
| `tgBotBackup`  | `false`                    | Прикладывать резервную копию БД к периодическому отчёту. |
| `tgCpu` / `tgMemory` | `80` / `80`          | Пороги оповещений по CPU / памяти (в процентах). |
| `tgLang`       | `en-US`                    | Язык прежних инструментов администратора; меню аккаунта и администратора на китайском. |
| `tgEnabledEvents` | `login.attempt,cpu.high`| Какие события доставлять.                       |

<Callout type="warn">
  Токен бота управляет вашим ботом — храните его в секрете и добавляйте только
  **доверенные** админские chat ID. Оповещения о входе никогда не содержат
  паролей.
</Callout>

<Callout type="info">
  Уведомления по электронной почте (SMTP) дублируют те же события
  (`smtpEnabledEvents`), если вы предпочитаете получать оповещения на почту —
  настройте SMTP в настройках панели.
</Callout>
