代理面板是高价值目标。几层加固措施就能带来很大改善。

## 面板加固

- 强而唯一的凭据，并启用**双因素认证**（TOTP）。
- 使用非默认的面板端口，以及一个长且随机的 Web 根路径。
- 为面板启用 TLS（直接启用，或通过[反向代理](/docs/operations/reverse-proxy)）。
- 内置的**登录限制器**会在某个 IP/用户名于 5 分钟内连续 5 次登录失败后将其封锁
  （封锁 15 分钟），并且面板可以将自身的出站流量经由某个 outbound 路由出去。

完整的检查清单请参见[首次登录](/docs/guide/first-login)。

## IP 限制

为每个客户端设置 **IP 限制**（参见[客户端](/docs/config/clients)），限制它同时在线的网络数，
按面板管理的所有服务器合计：一个 IPv4 /24 算一个网络，一个 IPv6 /64 也算一个。手机流量的
运营商 NAT 会让同一台手机同时从地址池里的几个地址出去，按单个 IPv4 地址计会把一台手机算成
好几个。网段里有面板自己的服务器或白名单地址时，只按这个地址本身计，封禁永远不会挡住中转。

限制由面板自己执行，不需要 Fail2ban，也不需要防火墙规则。

- 客户端超出限制时，最久未活动的网络会对该客户端封禁一段时间（面板设置中的
  **IP 限制封禁时长**，默认 **30 分钟**）。封禁是为该客户端服务的每台服务器 Xray 配置里的
  一条路由规则，生效时不重启 Xray；同一地址后的其他用户不受影响。
- 面板自己的服务器（每个节点的地址，以及其 agent 连接面板时的地址，因此中转服务器也包括
  在内）、**IP 限制白名单**和内网地址永远不会被计入或封禁。
- 管理面板和客户端自己的门户都会显示已占用的名额（如 `2/3`）、当前在线的 IP 及其服务器，
  以及正在生效的封禁和剩余时间；管理员可以提前解除封禁。中转地址永远不会出现在这里。每次
  封禁和解除也会写入 `/var/log/x-ui/3xipl-banned.log`（`x-ui banlog`）。

封禁开始时已建立的连接会持续到自行关闭；来自被封网络的新连接会被拒绝。

## 防滥用

面板可以检测滥用服务器的账号：发送垃圾邮件、BT 下载、端口扫描、网络攻击、爬虫、无故反复测速、
长时间满速占用，以及在 AI、Google 和微软平台批量注册账号。它只看连接和流量，从不看内容，所以下载软件等正常使用不会被算作违规。不出面板服务器的连接也不计入：
被封禁设备撞进黑洞的重试，以及中转转发到下一台服务器的连接，真实目的地由下一台服务器自己检查。

- **按服务器开启，默认关闭。** 在 **防滥用** 页面，每台服务器（面板本机的核心和每个 agent 节点）
  可以设为 **关闭**、**观察** 或 **封禁**。观察只记录并通知管理员；封禁模式按每条规则的设置处理。
  建议先观察一周左右，再根据记录调整阈值。agent 没有报告当前 `abuse-v3` 能力的服务器，
  页面会标为需要更新。
- **规则。** 在封禁模式的服务器上，每条规则可以设为 **只记录**（通知管理员）、**提醒用户**
  （不计违规）或 **封禁**。长时间满速 2 小时提醒；规则设为封禁时，4 小时计一次违规。
- **违规与停用。** 每次违规在所有服务器上封禁账号 30 分钟。30 天内第 4 次违规会停用账号，直到
  管理员解除；解除停用同时清除违规次数。IP 限制的封禁记在同一份记录里，但不计入违规次数。
- **批量注册 AI/Google/微软账号。** 面板看各平台自己的登录或注册服务器：`auth.openai.com`
  （ChatGPT）、`accounts.google.com`（Google，含 Gemini）和 `signup.live.com`（微软），统计账号
  在 1 小时和 24 小时内有多少分钟连过它们：正常登录只要一两分钟，批量注册会一直连。OpenAI 和微软
  超过上限就记一次。Google 的服务器还会收到浏览器和手机的后台检查，所以只超一小时记为「可疑」（只给
  管理员看，不计违规、不提醒用户）；一天内有几个小时超限（默认 3 个），或一小时超过上限的 1.5 倍，
  才记一次。当天用过接码、临时邮箱或打码网站时，各平台超过每小时上限的一半就记一次，并写出是哪个
  网站；指纹浏览器不算，普通用户也在用。每条记录还会写出账号那一小时的流量。它分不出登录和注册，
  也数不出注册了几个账号；即使在封禁模式的服务器上，这条规则也只记录，直到你改了它的处理方式。
- **注册保护。** 用户页面按网络（IPv4 /24 或 IPv6 /48）统计 24 小时内的注册数。达到上限（默认
  3 个）时，会把该网络注册的账号通知管理员；设为阻止注册时，该网络在 24 小时内不能再注册。
- **通知。** 封禁、停用和提醒会发到用户绑定的 Telegram 和管理员。只记录的检测中，端口扫描和
  网络攻击立即通知管理员，其余汇总在每天 09:00（北京时间）的日报里。
- **用户能看到什么。** 用户页面打开时会先弹出使用须知，最醒目的是提醒手机关闭定位服务；可以
  直接关闭，或 7 天内不再提示。用户页面和机器人都会列出账号最近 90 天的封禁记录，包括时间和原因。

封禁和 IP 限制一样是路由规则：已建立的连接会持续到自行关闭，新连接会被拒绝。管理员可以在防滥用
页面、用户对话框或机器人的用户卡片里解除封禁或清除违规次数。

只开放你实际使用的端口：SSH、面板端口、订阅端口以及你的入站端口。`x-ui` 菜单
（**22 — Firewall Management**）封装了 `ufw`，或者你也可以在此生成规则：

  可能把自己锁在外面。请在保留第二个会话的情况下进行测试。
</Callout>

## 网络调优（BBR）

`x-ui` 菜单（**25 — Enable BBR**）用于切换 Google 的 BBR 拥塞控制算法
（`net.ipv4.tcp_congestion_control = bbr`、`net.core.default_qdisc = fq`），它在拥塞链路
上通常能提升吞吐量。
